### physics.py — physics-based daily yield model
Implement a transparent, documented model with all constants at the top and docstrings explaining the equations:

1. **Plane-of-array irradiance**: convert daily GHI to plane-of-array irradiance for a tilted, south-facing panel using a simple geometric transposition: compute daily-average solar elevation from latitude and day-of-year (declination formula), then `poa = ghi * max(cos(lat - tilt - decl), 0.05) / max(cos(lat - decl), 0.05)` — clearly comment that this is a first-order approximation (no diffuse/direct split). Default tilt = latitude.
2. **Cell temperature**: `t_cell = t_amb + (NOCT - 20) / 800 * G_avg` where `G_avg` is the daytime-average irradiance in W/m² (estimate as `poa * 1000 / daylight_hours`; compute daylight hours from latitude and declination). NOCT default 45 °C.
3. **Temperature derating**: `eff_factor = 1 + gamma * (t_cell - 25)`, gamma default `-0.0040 /°C`.
4. **System losses**: single `performance_ratio` default 0.80 (soiling, wiring, inverter, mismatch) — expose as a parameter and document it. Add an optional dust/soiling penalty parameter for Pakistan (default 0.03) with a comment explaining why.
5. **Daily energy**: `E_kwh = P_stc_kw * poa * eff_factor * performance_ratio`.

Function: `physics_yield(df, lat, system_kw=5.0, tilt=None, azimuth=180, gamma=-0.004, noct=45, pr=0.80, soiling=0.03) -> pd.Series` (kWh/day).

Also implement `clear_sky_index = ghi / ghi_clear` as a helper (clip 0–1.2).

## STAGE 2 — ML model and evaluation

Add a machine-learning forecaster and a fair comparison against the physics model.

### ml.py
- Features per day: `ghi`, `ghi_clear`, `clear_sky_index`, `t_amb`, `t_max`, `t_min`, `rh`, `wind`, `precip`, `day_of_year` (as sin/cos), lagged `ghi` for the previous 1, 2, 3 and 7 days, 7-day rolling mean of `ghi`.
- Target: **next-day** PV energy (kWh) — the physics model's output on the true next-day weather is the label. Document clearly that this is a proxy target because we have no metered plant data, and that the model is learning to forecast tomorrow's yield from today's weather history.
- Two models: (1) `LightGBMRegressor`, (2) `sklearn` `GradientBoostingRegressor` as a fallback if LightGBM isn't available.
- Persistence baseline: predict tomorrow = today.
- Time-based split only: train on the first 70% of days, validate on the next 15%, test on the last 15%. Never shuffle.
- Save trained model with joblib into `data/models/{city}.pkl`.

### evaluate.py
- Metrics: RMSE, MAE, MAPE (ignore days with energy < 0.5 kWh), R², and skill score vs persistence = `1 - RMSE_model / RMSE_persistence`.
- Function `compare(city, start, end, system_kw)` that returns a DataFrame with one row per model (persistence, physics-with-tomorrow's-true-weather as upper bound, LightGBM) and the metrics.
- Feature importance (gain) from LightGBM as a Series.

### plots.py
Functions returning plotly figures: (a) daily yield time series with actual vs predicted on the test window; (b) monthly total yield bar chart; (c) scatter predicted vs actual with 1:1 line; (d) feature importance bar chart; (e) residuals by month.

### Tests
